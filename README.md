# Einkaufszettel

Eine gemeinsam nutzbare Einkaufsliste für Home Assistant mit eigener Produkt- und Kategorienlogik sowie Alexa-Anbindung über eine vorhandene HA-To-do-Liste.

> **Projektstatus:** Alpha. Enthält HA-Quelllistenverwaltung, automatischen Quellabgleich, gemeinsame Produktkategorien und Supermärkte mit eigener Kategorienreihenfolge sowie eine installierbare Offline-PWA. Die Integration erzeugt keine zusätzlichen To-do-Listen. Ein eigenständiger Produktkatalog ist noch nicht implementiert.

## Funktionsumfang

- Vorhandene externe HA-To-do-Listen werden unter **Setup → Listen verwalten** in der App angeboten. Dort werden Listen aktiviert und kurze App-Anzeigenamen vergeben.
- Offene Einträge werden beim ersten Aktivieren in einen internen HA-Speicher kopiert.
- Ein Button ergänzt später neue, offene Quell-Einträge anhand ihrer Quell-IDs, ohne vorhandene lokale Änderungen zurückzusetzen.
- Die PWA unterstützt Hinzufügen, Abhaken/Wiederöffnen, Umbenennen und Löschen. Es erscheint keine doppelte Einkaufszettel-Liste in der HA-To-do-Ansicht.
- Name und Status werden automatisch mit der Quelle abgeglichen; App-Änderungen werden zurückgeschrieben, soweit die Quelle die jeweilige Aktion unterstützt. Zusatzinformationen bleiben in unserem HA-Speicher.
- Produktkategorien werden gemeinsam gespeichert und alphabetisch A–Z verwaltet. Je Supermarkt lassen sich Kategorien auswählen und unabhängig sortieren. Die Hauptliste verwendet dezente Kategorieüberschriften mit Trennlinien.
- Zu jedem Supermarkt kann eine Bonuskarten- oder APP-Code-Grafik hinzugefügt werden. Das Bild wird gemeinsam in Home Assistant gespeichert und beim Start des Kassiervorgangs zusammen mit der Pfandbon-Erinnerung angezeigt.
- Artikel können eine Kategorie, eine Mengenangabe als Freitext und Zusatzinformationen erhalten. Diese Daten werden mit der vorhandenen Offline-Warteschlange gespeichert; ein Produktkatalog und strukturierte Mengeneinheiten sind noch nicht implementiert.
- Die Smartphone-Oberfläche wird als PWA von der Integration über Home Assistant ausgeliefert. App-Dateien und Listendaten werden lokal gespeichert; Hinzufügen, Abhaken und Löschen werden offline vorgemerkt und beim nächsten Verbinden synchronisiert.

## Installation mit HACS

1. In HACS das Repository `https://github.com/Rasenkardinal/Einkaufszettel` als **Integration** hinzufügen oder den bereits vorhandenen Repository-Eintrag aktualisieren.
2. Das aktuelle Release herunterladen.
3. Home Assistant neu starten.
4. **Einstellungen → Geräte & Dienste → Integration hinzufügen → Einkaufszettel** öffnen.
5. Einrichtung bestätigen. Die Quelllisten werden anschließend in der App verwaltet.
6. In der Web-App **Setup → Listen verwalten** öffnen, gewünschte HA-Listen aktivieren und kurze Anzeigenamen vergeben. Diese Einstellungen benötigen HA-Administratorrechte und gelten für alle Haushaltsmitglieder.
7. Die neue Einkaufszettel-Seite erscheint in der Home-Assistant-Seitenleiste. Dort die Liste öffnen. Der Button **„Web-App öffnen / installieren“** unter den Integration-Entitäten erzeugt zusätzlich eine Benachrichtigung mit dem direkten App-Link.

Die Installation benötigt HTTPS, beispielsweise über Nabu Casa. Die PWA muss mindestens einmal online geladen und synchronisiert worden sein, bevor sie offline verwendet werden kann. Im installierten Modus kann sie ohne normale Browser-Adressleiste starten. Der Installationsdialog wird abhängig vom Browser angeboten; auf iOS kann stattdessen die Browserfunktion **Teilen → Zum Home-Bildschirm** nötig sein.

Nach einem Update die Web-App online neu laden. JavaScript und CSS tragen eine gemeinsame Versionskennung, damit eine neue HTML-Seite keine alten Dateien aus dem Offline-Cache verwendet. Nach dem Laden des aktualisierten Offline-Caches ist die neue Oberfläche auch ohne Netz verfügbar. Browserdaten müssen dafür nicht gelöscht werden.

## Wichtige Umstellung von Easy Shopping (`easy_shopping`)

Diese Version ändert die technische HA-Domain von `easy_shopping` auf `einkaufszettel`. Home Assistant kann Config Entries nicht domainübergreifend migrieren. Deshalb wird eine neue Integrationseinrichtung benötigt. Der neue Konfigurationsflow kann jedoch vorhandene lokale Eintragsdaten aus einem passenden alten `easy_shopping`-Config-Entry übernehmen, wenn dieser noch in HA registriert ist und dieselbe Quell-Entity ausgewählt wird.

1. Vor dem Update ein Home-Assistant-Backup erstellen, einschließlich `.storage`.
2. HACS aktualisieren und **Einkaufszettel `0.3.0-alpha.3`** herunterladen. Home Assistant neu starten.
3. Den bisherigen Easy-Shopping-Eintrag **nicht vorher löschen**. Unter **Einstellungen → Geräte & Dienste → Integration hinzufügen** die neue Integration **Einkaufszettel** hinzufügen.
4. In der neuen Web-App unter **Setup → Listen verwalten** dieselbe Alexa-/Quell-To-do-Entity aktivieren. Dadurch kann die Integration den alten lokalen Snapshot anhand der Quell-Entity übernehmen, ohne die Alexa-Liste erneut zu importieren. Die alte Integration darf bis zur erfolgreichen Prüfung registriert bleiben.
5. Einträge und Erledigt-Status in der Web-App prüfen. Eigene Einkaufszettel-To-do-Entitäten werden nicht mehr bereitgestellt; darauf basierende Dashboards und Automationen müssen angepasst werden.
6. Erst danach den alten **Easy Shopping**-Config-Entry löschen. Die alte `.storage/easy_shopping.<entry_id>`-Datei wird dadurch nicht automatisch gelöscht.

**Nicht** den alten Config-Entry entfernen, bevor die neue Liste geprüft ist. Falls er bereits gelöscht wurde, kann die Integration den zugehörigen alten Store nicht sicher anhand der Quellliste identifizieren; dann ist ein Restore aus Backup oder ein neuer Import aus der Quellliste erforderlich. Ein neuer Eintrag wird für den Store-Pfad `.storage/einkaufszettel.<entry_id>` angelegt.

## Manuelle Installation

Home Assistant mit To-do-Unterstützung und eine externe Quellliste als `todo`-Entity sind erforderlich. Den vollständigen Ordner [custom_components/einkaufszettel](custom_components/einkaufszettel) in den HA-Konfigurationsordner unter `custom_components/einkaufszettel` kopieren und Home Assistant neu starten. Die Integration verwaltet keine Alexa-Anmeldung und benötigt keine Amazon-Zugangsdaten.

Das Integrationslogo wird von Home Assistant ab Version 2026.3 direkt aus `custom_components/einkaufszettel/brand` geladen. Ältere HA-Versionen zeigen bei Custom Integrations weiterhin kein lokales Markenlogo an.

## Quellliste erneut kopieren

Unter **Einstellungen → Geräte & Dienste → Einkaufszettel → Entitäten** den Button **„Einkaufszettel: Quellliste kopieren“** öffnen und **Drücken** wählen. Der Button kann auch in ein Dashboard gelegt oder mit `button.press` aufgerufen werden.

- Nur unbekannte, offene Quell-IDs werden hinzugefügt; wiederholtes Drücken erzeugt keine Duplikate.
- Vorhandene lokale Namen, Beschreibungen, Fälligkeiten und Erledigt-Status bleiben erhalten. Abgehakte Artikel werden nicht wieder geöffnet.
- Gleicher Name mit einer neuen Quell-ID gilt als neuer Eintrag. Fehlen stabile Quell-IDs, wird mit einer Fehlermeldung abgebrochen statt nach Namen zu raten.
- Der Kopierbutton selbst spiegelt keine Quelländerungen und -löschungen zurück; der separate automatische Quellabgleich übernimmt diese nach den unten beschriebenen Synchronisationsregeln. Bei nicht erreichbarer Quelle oder fehlgeschlagenem Speichern bleibt der lokale Bestand beim Kopieren unverändert.

## Offline-Web-App verwenden

Das Dreipunktmenü trägt die Überschrift **Einstellungen** und ist in direkt aufklappbare Untermenüs mit Plus/Minus statt Pfeilen gegliedert. Mehrere Bereiche können gleichzeitig geöffnet bleiben. Escape schließt zunächst den fokussierten Bereich und danach das Menü:

Auch **Supermärkte verwalten** und **Produktkategorien verwalten** verwenden dieselben Gruppenüberschriften, Schrift und Plus/Minus-Anzeigen. Im aufgeklappten Bereich öffnet **Supermarktverwaltung öffnen** bzw. **Kategorieverwaltung öffnen** die jeweilige Verwaltungsseite.

- **Installation:** HA-Anmeldung, App-Installation sowie Browser-/HA-Links zum Öffnen und Testen.
- **Design:** Klappt die Farbauswahl direkt im Menü auf, ohne Flyout oder zusätzlichen Dialog. Die acht dunklen Farbschemata sind erst nach dem Aufklappen sichtbar: **Botanical**, **Midnight Plum**, **Market Journal**, **Fresh Signal**, **Mono** (Standard), **Tomato**, **Lime Focus** und **Indigo Pocket**. Farbpunkte zeigen die Akzentfarben; Rahmen und Häkchen markieren die aktive Auswahl. Änderungen sind sofort sichtbar und werden auf diesem Gerät auch offline für alle Listen gespeichert. Die Auswahl lässt das Untermenü geöffnet. Schrift und Aufbau bleiben gleich.
- **Listenverwaltung:** **Listen verwalten** (Quellen, App-Namen und Sichtbarkeit) und **Quelllisten abgleichen**. Der Abgleich ergänzt die automatische Synchronisation von Name und Status; die kompatible manuelle Kopierfunktion bleibt über den HA-Button verfügbar.
- **Supermärkte verwalten:** Eigenständige Übersichts- und Bearbeitungsseiten zum Anlegen, Umbenennen und Löschen nach Bestätigung. **Produktkategorien für diesen Markt bearbeiten** öffnet eine weitere Seite mit Kategorienauswahl aus dem gemeinsamen Speicher, großen 48×48-Pixel-Verschiebegriffen und Hoch-/Runter-Schaltflächen. Beim Ziehen folgt eine angehobene Zeile dem Finger oder der Maus; die Reihenfolge aktualisiert sich sofort und am Bildschirmrand wird automatisch gescrollt. Ziehen startet nur am Griff, außerhalb bleibt normales Scrollen möglich. Escape oder ein unterbrochener Ziehvorgang stellt die vorherige Reihenfolge wieder her. Griffe unterstützen zusätzlich die Pfeiltasten. Die Auswahl erfolgt auf einer eigenen A–Z-Seite. **Bonuskarten oder APP-Codes einbinden** nimmt ein Bild aus Dateien oder mit der Kamera auf; das optimierte Bild wird für alle Geräte gemeinsam gespeichert. Entfernen löscht nur das Bonuskartenbild. Erst **Speichern** übernimmt Änderungen in Home Assistant, **Abbrechen** verwirft den Entwurf.
- **Produktkategorien verwalten:** Eigenständige A–Z-Übersicht sowie Erstellungs-/Bearbeitungsseite. Eine gelöschte Kategorie wird aus allen Marktzuordnungen entfernt. Artikel bleiben bestehen und erscheinen unter **Ohne Kategorie**. Auch die Listenverwaltung öffnet eine eigene Seite statt eines Dialogs.

Der gemeinsame Kategorien- und Marktkatalog liegt unter `.storage/einkaufszettel.supermarkets`; vorhandene Marktdaten bleiben erhalten. Änderungen benötigen HA-Administratorrechte und eine Online-Verbindung. Bereits geladene Daten sind offline lesbar, Verwaltungsänderungen werden jedoch nicht offline vorgemerkt. Ungespeicherte Änderungen werden beim Verlassen abgefragt.

Rechts neben **Auf der Liste** lässt sich unabhängig von der Einkaufsliste ein Supermarkt auswählen, alternativ **Ohne Markt**. Die Auswahl öffnet dasselbe kompakte Flyout wie der Listentitel, mit Häkchen am aktiven Markt und derselben Tastaturbedienung. Es ist immer nur eine der beiden Auswahlen geöffnet. Die Auswahl wird je Liste auf diesem Gerät gespeichert. Die Hauptliste gruppiert Artikel nach der gewählten Marktreihenfolge; weitere Kategorien folgen A–Z. Ohne Markt werden alle Kategorien A–Z angezeigt. Leere Gruppen werden ausgeblendet. Artikelkarten bleiben im bisherigen Design; optionale Mengen und Zusatzinformationen erscheinen als dezente zweite Zeile. Zum Zuordnen oder Ändern den Artikelnamen etwa eine halbe Sekunde gedrückt halten (Finger oder Maus). Kurzes Antippen öffnet keine Details; Scrollen und Wischen brechen das lange Drücken ab. Per Tastatur lässt sich der fokussierte Artikel weiterhin mit Enter oder Leertaste bearbeiten. Die Checkbox reagiert weiterhin sofort.

**Planen / Einkaufen:** Rechts neben dem Listennamen, unmittelbar vor dem Sync-Pfeil, wechselt ein umrandeter Iconbutton den Ansichtsmodus. Der Warenkorb startet den **Einkaufsmodus**: Die Eingabeleiste verschwindet und **Ohne Kategorie** folgt der gespeicherten Marktreihenfolge; ohne festgelegte Position steht die Gruppe zuletzt. In der Markt-Kategorienverwaltung lässt sich **Ohne Kategorie** wie eine Kategorie verschieben, aber nicht entfernen. Der Stift führt zurück zum **Planungsmodus**: Die Eingabeleiste ist sichtbar und **Ohne Kategorie** steht immer ganz oben. Standard ist Planen. Die Auswahl gilt auf diesem Gerät für alle Listen, wird auch offline gespeichert und verändert keine Artikel, Kategorien oder gemeinsamen Listeneinstellungen. Ein bereits eingetippter Artikel bleibt beim Wechsel erhalten. Abhaken, Wischen und Bearbeiten per Longpress funktionieren in beiden Modi. Tooltip und zugängliche Buttonbeschriftung nennen aktuellen Modus und Zielaktion.

Die nachfolgenden Verweise auf **Setup → Listen verwalten** meinen **Einstellungen → Listenverwaltung → Listen verwalten**; Anmeldung und Installationslinks liegen unter **Installation**.

Beim Verlassen ungespeicherter Katalogänderungen fragt ein Dialog im App-Design mit **Weiter bearbeiten** und **Änderungen verwerfen** nach. Escape bricht das Verlassen ab; beim Schließen des Browserfensters bleibt aus technischen Gründen die browserseitige Warnung bestehen. In der Hauptliste sind Artikelname und Checkbox vertikal zentriert. Zusatzinformationen erscheinen mit 13 px; die Textspalten sind im Verhältnis 52 % Artikelname zu 48 % Zusatzinfo aufgeteilt. Lange Texte werden weiterhin gekürzt und sind im Artikeldialog vollständig lesbar.

Zum Übernehmen gemeinsamer Listeneinstellungen muss die App mit einem HA-Administrator angemeldet sein. Ohne diese Berechtigung wird eine ausdrückliche Fehlermeldung angezeigt; bestehende Einstellungen bleiben unverändert.

Die Listenauswahl öffnet direkt am Listentitel ein kompaktes Flyout (Entwurf **01 · Purist**). Es zeigt Listennamen und ein Häkchen an der aktiven Liste statt eines nativen Systemdialogs. Auswahl per Tippen oder Tastatur; Pfeiltasten, Pos1/Ende, Escape und Klick außerhalb werden unterstützt. Bereits geladene Listen bleiben offline auswählbar. Aktive Artikel haben hellere Flächen; erledigte Artikel werden ausgegraut und durchgestrichen, lassen sich aber weiterhin wieder öffnen, bearbeiten und löschen.

Die HA-Seitenleiste zeigt genau einen gemeinsamen Eintrag **Einkaufszettel**, unabhängig von der Anzahl aktivierter Listen. Die gewünschte Liste wird innerhalb der App ausgewählt. Nach dem Update Home Assistant neu starten, damit die bisherigen separaten Seitenleistenpunkte entfernt werden.

1. In Home Assistant die neue **Einkaufszettel-Seite in der Seitenleiste** öffnen. Sie zeigt die Web-App direkt in Home Assistant; sie ist der normale Startweg.
2. Oben rechts das **Dreipunkte-Menü (Setup)** öffnen und **„App in eigenem Browserfenster öffnen / installieren“** wählen. Für Installation und Offline-Betrieb die HTTPS-Adresse verwenden, zum Beispiel über Nabu Casa. Im eigenen Browserfenster beim ersten Aufruf im Setup **Mit HA verbinden** wählen und Home Assistant den Zugriff erlauben; dann über **App installieren** oder das Browsermenü zum Startbildschirm hinzufügen.
3. Beim nächsten Einkauf das Homescreen-Symbol direkt starten; ohne Installation die Einkaufszettel-Seite in der HA-Seitenleiste öffnen.
4. Artikel hinzufügen, abhaken oder entfernen. Ohne Netz werden Änderungen in der lokalen Browser-Datenbank und einer dauerhaften Warteschlange gespeichert. Beim nächsten Start mit erreichbarem HA werden diese nacheinander übertragen.
5. Der farbige Kreispfeil rechts neben dem Listentitel stößt die Synchronisierung an; der separate Pfeil öffnet den Online- und Sync-Status, ohne die Liste zu verschieben. Nach Verbindungsabbrüchen verbindet sich die App automatisch erneut und synchronisiert vorgemerkte Änderungen. Nur bei abgelehnter oder widerrufener Anmeldung unter **Installation → Mit HA verbinden** die Anmeldung erneut erlauben. Der automatische Abgleich mit Alexa-/Quelllisten benötigt eine Verbindung; Fehler der Quelle werden getrennt von bereits in HA gespeicherten App-Änderungen angezeigt.

Die Wiederverbindung verwendet Wartezeiten von 1, 2, 4, 8, 16 und maximal 30 Sekunden. Beim Zurückkehren zur App, nach Wiederherstellung des Netzes und beim Wiederanzeigen einer Seite wird die Verbindung erneut geprüft. Ping/Pong prüft eine angemeldete Verbindung alle 30 Sekunden; ohne Antwort innerhalb von 15 Sekunden wird sie neu aufgebaut. Auch ein nicht abgeschlossener Verbindungsaufbau wird nach 15 Sekunden erneut versucht. Netzwerkfehler und vorübergehende Serverfehler bei der Token-Erneuerung verlangen keine neue Anmeldung. Ein abgelehntes Zugriffstoken wird einmal automatisch erneuert; lehnt HA auch diese Anmeldung ab, wird ausdrücklich eine neue Freigabe angefordert.

Die App verwendet ausschließlich die Adresse, unter der sie geöffnet wurde, ohne automatischen Wechsel zur lokalen IP. Für die installierte App möglichst dieselbe HTTPS-Adresse verwenden. Lokale IP, Nabu-Casa-Adresse und andere Domains haben getrennte Browser-Speicher einschließlich Anmeldung und Offline-Änderungen.

Die Verbindungsregressionen lassen sich ohne zusätzliche Pakete prüfen: Repository per HTTP bereitstellen (z. B. `python -m http.server 8774 --bind 127.0.0.1`) und `/tests/frontend/connection.html` öffnen. Die Seite testet die Verbindungsfunktionen aus dem aktuellen App-Skript mit simulierten Timern, WebSocket und Anmeldung; sie greift nicht auf Home Assistant zu.

`/tests/frontend/categories.html` prüft die Verwaltungsseiten, A–Z-Auswahl, Markt-Reihenfolge, Drag-and-drop/Tastatur, Gruppierung, Zusatzinformationen und Speicherfehler. Außerdem deckt sie das Kategorie-Suchflyout, die Fokusführung im Artikeldialog und den Sync-Status ohne Layoutsprung mit isolierten Beispieldaten ab. `/tests/frontend/sync.html` prüft weiterhin die Offline-Synchronisation. Keine dieser Testseiten ändert echte HA-Daten.

### Synchronisationsregeln

- **HA ist der zentrale Speicher.** Apps übertragen kleine Feldänderungen, keine vollständigen Listen als Ersatz. Bei Änderungen desselben Feldes gewinnt die zuletzt in HA unter dem Listen-Lock angenommene Änderung. Eine später übertragene alte Offlineänderung kann deshalb eine neuere Eingabe überschreiben. Geräteuhren entscheiden nicht über Konflikte.
- **Dauerhafte Bestätigungen:** Jede Aktion hat eine unveränderliche ID. HA speichert ihren Inhalt und das Ergebnis zusammen mit dem Artikelstand. Eine Wiederholung nach verloren gegangener Antwort oder Neustart erhält eine Bestätigung, ohne die Änderung erneut anzuwenden. Die App speichert neuen Stand und Warteschlangenentfernung in derselben IndexedDB-Transaktion. Eine Listenrevision kennzeichnet den Stand; derzeit werden vollständige Snapshots übertragen, kein Delta-Verlauf.
- **Feldweise Änderungen:** Name, Status, Beschreibung und Fälligkeit sind unabhängig. `metadata` enthält zusätzliche benannte Textwerte bzw. `null`, z. B. `product_id`, `category_id`, `quantity`, `unit` und `note`. Ein Metadatenpatch ändert nur die angegebenen Schlüssel. Diese Daten werden zwischen Apps synchronisiert, aber nie aus fehlenden Quellfeldern gelöscht.
- **Dauerhafte Produktkategorien:** Die Kategorie ist nicht mehr nur eine Eigenschaft eines einzelnen Einkaufsartikels. Eine Zuordnung in der Listensicht speichert zusätzlich eine gemeinsame Produktregel im HA-Katalog (`einkaufszettel.supermarkets`, Feld `products`). „Milch“, „milch“ und „ MILCH “ gelten als dasselbe Produkt; Groß-/Kleinschreibung und wiederholte Leerzeichen werden vereinheitlicht, es gibt keine unscharfe Zuordnung verschiedener Namen wie „Milch“ und „Hafermilch“. Die Regel gilt für alle Listen und Geräte, einschließlich neuer Alexa-/HA-Importe, und bleibt beim Abhaken oder Löschen des Einkaufsartikels erhalten. Bestehende Zuordnungen aus gespeicherten Artikeln (auch erledigten und noch vorhandenen Löschvermerken) werden beim Laden übernommen. Bei bereits widersprüchlichen Altzuordnungen wird die zuerst übernommene Regel verwendet; eine neue ausdrückliche Zuordnung in der Listensicht ersetzt sie für alle Listen. Andere Artikeldaten wie Notizen und Menge bleiben unverändert. Nicht mehr gespeicherte historische Artikel lassen sich nicht nachträglich rekonstruieren.
- **Zugeordnete Produkte:** Unter **App-Menü → Produktkategorien → Kategorie bearbeiten → Zugeordnete Produkte** stehen die dauerhaft zugeordneten Produkte alphabetisch, unabhängig davon, ob sie gerade auf einer Einkaufsliste stehen. **Entfernen** benötigt eine Sicherheitsbestätigung und löst nur die Kategoriezuordnung; Einkaufsartikel werden nicht gelöscht. Ein ausdrücklicher „keine Kategorie“-Vermerk verhindert, dass alte Artikel oder ein Neustart die entfernte Zuordnung wieder einlernen. Auch „Ohne Kategorie“ in der Artikelbearbeitung löst die Produktzuordnung. Erst eine erneute manuelle Kategoriezuordnung stellt sie wieder her. Entfernen über die Kategorienverwaltung benötigt wie die übrigen Katalogänderungen eine Verbindung und HA-Administratorrechte. Bestehende Artikel anderer Listen übernehmen die neue Regel spätestens beim nächsten Abruf/Abgleich.
- **Produktregeln offline und bei Wiederholungen:** Die App speichert Produktregeln zusätzlich in der Offline-Kopie und überlagert sie mit noch ausstehenden manuellen Kategorieänderungen. Eine Neuanlage kann damit auch offline die bekannte Kategorie übernehmen. HA speichert globale Produktaktionen mit dauerhaften Bestätigungen vor dem zugehörigen Listensnapshot. Schlägt einer der Speicherschritte fehl, wird die Aktion nicht als abgeschlossen bestätigt; der Client behält sie zur Wiederholung. Die globale Zuordnung kann in diesem Fehlerfall bereits gespeichert sein. Ihre Bestätigung verhindert, dass ein späterer Wiederholungsversuch eine inzwischen manuell entfernte Zuordnung erneut setzt.
- **Automatischer Quellabgleich:** Jede eingeblendete Liste wird in HA alle 30 Sekunden geprüft, auch ohne geöffnete App. Eine sichtbare, verbundene App gleicht ebenfalls alle 30 Sekunden und nach eigenen Änderungen ab. Über **Listenverwaltung → Quelllisten abgleichen** oder die Sync-Schaltfläche lässt sich der Abgleich anstoßen. Es gibt keine garantierte Echtzeit-Zustellung; hinzu kommt das Aktualisierungsintervall der Alexa-Anbindung selbst.
- **Flüssige Bedienung auch online:** Abhaken, Löschen, Bearbeiten und Hinzufügen werden zuerst dauerhaft auf dem Gerät gespeichert und sofort angezeigt. Die Oberfläche wartet nicht auf HA oder Alexa; auch während des Abgleichs sind weitere Eingaben und Listenwechsel möglich. Schnell aufeinanderfolgende Aktionen werden etwa 150 ms gebündelt und in einem einzigen Hintergrundlauf geordnet übertragen. Nach eigenen Änderungen werden nur betroffene Listen abgeglichen; der regelmäßige und manuelle Gesamtabgleich bleiben erhalten. Neue Aktionen während einer laufenden Übertragung werden anschließend weiter abgearbeitet. Serverantworten werden mit der noch unbestätigten lokalen Warteschlange überlagert, damit verspätete Antworten keine neueren Eingaben zurücksetzen. Bei Verbindungsfehlern bleibt die Warteschlange erhalten; Wiederverbindung, regelmäßiger oder manueller Abgleich versuchen die Übertragung erneut. Nur Verwaltungsaktionen und der kurze lokale Listenwechsel können ihre bisherigen Bediensperren verwenden; Netzwerk-Sync sperrt die Einkaufsliste nicht.
- **Drei-Wege-Vergleich:** Für jede Quell-ID wird der zuletzt bestätigte Stand von Name und Status gespeichert. Unveränderte alte Quellwerte überschreiben keine lokalen Änderungen. Tatsächliche Quelländerungen gelten zum Zeitpunkt ihrer Erkennung in HA als neue Änderungen. Ändern beide Seiten dasselbe Feld vor dem Abgleich, gewinnt die dann erkannte Quelländerung. Nicht kollidierende lokale Änderungen bleiben erhalten und werden zurückgeschrieben.
- **Quellgrenzen:** Automatisch abgeglichen werden Name und erledigt/offen, sofern die konkrete HA-To-do-Quelle Schreiben unterstützt. Beschreibung, Fälligkeit und sämtliche Zusatzinformationen bleiben integrationsverwaltet; für bestehende Artikel werden sie nicht aus der Quelle überschrieben. Neue offene Quellartikel werden importiert, alte unzugeordnete erledigte Quellartikel nicht. Rein lokale, schon erledigte Artikel werden nicht nachträglich als offene Artikel in Alexa angelegt.
- **Erneutes Hinzufügen per Alexa:** Ein bisher unbekannter offener Quellartikel öffnet einen eindeutig passenden erledigten lokalen Artikel wieder, statt eine zweite Position anzulegen. Verglichen wird nur innerhalb derselben Liste, ohne Groß-/Kleinschreibung und mit vereinheitlichten Leerzeichen; es gibt keine unscharfe Namenssuche. Lokale Artikel-ID, Kategorie, Produktzuordnung, Menge, Notizen und weitere Zusatzdaten bleiben erhalten; Name und offene Quell-ID werden übernommen. Die vorherige Quell-ID wird dauerhaft als abgelöst gespeichert und danach ignoriert, auch nach HA-Neustart und beim alten manuellen Kopierer. Die erledigte Alexa-Position wird nicht gelöscht. Bereits offene passende Artikel, mehrere passende erledigte Artikel oder mehrere gleichzeitig neue gleichnamige Quellartikel werden nicht automatisch zusammengeführt. Bereits vor dieser Änderung importierte Doppelpositionen werden nicht nachträglich automatisch bereinigt.
- **Löschen:** App-Löschungen erhalten dauerhafte Löschvermerke. Verspätete Bearbeitungen oder Anlagen derselben ID werden bestätigt, aber ausdrücklich als verworfen gemeldet; sie stellen den Artikel nicht wieder her. Entfernt die Quelle einen Artikel, bleibt er bei uns samt Zusatzdaten als erledigt erhalten. Ein anschließendes ausdrückliches Wiederöffnen legt bei Bedarf einen neuen Quellartikel an. Ein fehlgeschlagener Abruf, eine nicht verfügbare Quelle oder eine ungültige Antwort ist niemals eine leere Liste.
- **Wiederanlauf und Grenzen der Quellschnittstelle:** Änderungen und Löschungen werden anhand des bestätigten Quellstands erneut versucht. Vor einer Anlage wird dagegen eine dauerhafte Absicht gespeichert, weil `todo.add_item` keine verlässlich zuordenbare neue ID zurückgibt. Anschließend wird die neue Quell-ID anhand neu hinzugekommener passender Artikel bestätigt. Bei unbestätigtem oder mehrdeutigem Ergebnis wird die Anlage nicht blind wiederholt. Nur der betroffene Artikel wartet auf eine Entscheidung; andere Artikel werden weiter abgeglichen. Das verhindert automatische Doppelanlagen, ersetzt aber keine transaktionale Alexa-Schnittstelle.
- **Schreibweise der verbundenen Liste:** Manche Alexa-Anbindungen ändern Groß-/Kleinschreibung und Leerzeichen, z. B. von „SYNC TEST Brot“ zu „Sync test brot“. Bei Anlagenbestätigung, Wiederanlauf und Änderungsbestätigung werden diese Unterschiede ignoriert; die bestätigte Schreibweise wird übernommen. Eine Anlage wird trotzdem nur bestätigt, wenn genau eine neue, noch nicht zugeordnete ID passt. Mehrere passende Einträge bleiben ein Konflikt; ähnliche, aber andere Produktnamen werden nicht unscharf zusammengeführt.
- **Sync-Konflikte auflösen:** Die App fragt bei neuen unklaren Anlagen nach und bietet drei Entscheidungen: einen vorhandenen freien **Quellartikel zuordnen**, **bewusst erneut anlegen** (mit Warnung vor möglichen Duplikaten) oder **nur lokal behalten**. Bei einer Zuordnung bleiben die lokale Artikel-ID und Zusatzdaten erhalten; der lokale Name und Status werden anschließend in die Quelle übertragen. Ist der lokale Artikel bereits gelöscht, wird stattdessen der zugeordnete Quellartikel gelöscht; eine Neuanlage ist dann nicht möglich. „Später entscheiden“ ändert nichts; der Dialog lässt sich über den Konfliktknopf wieder öffnen. „Nur lokal“ wird dauerhaft gespeichert und kann später über „Nur lokale Artikel prüfen“ wieder aufgelöst werden. Bereits angezeigte Konflikte werden nicht nachträglich stillschweigend zugeordnet. HA prüft jede Entscheidung erneut gegen den aktuellen Stand; veraltete Entscheidungen eines zweiten Geräts oder inzwischen belegte/fehlende Quellartikel werden ausdrücklich abgewiesen.
- **Offline und Fehler:** App-Änderungen bleiben auch bei defekter, nicht verfügbarer oder schreibgeschützter Quelle in HA erhalten. Die App zeigt ausstehende Quellprobleme mit Listennamen an und meldet nicht pauschal vollständigen Erfolg. Ein Quellversuch ist auf zehn Sekunden begrenzt. Bereits laufende Abgleiche werden nicht parallel gestartet. Ausgeblendete Listen werden nicht automatisch abgeglichen.
- **Verständliche Zustände:** „Nur lokal“ bedeutet in unserer App-Liste und im zentralen HA-Speicher für alle Geräte, aber ohne Abgleich dieses Artikels mit der verbundenen HA-/Alexa-To-do-Liste. Ein eventuell bereits angelegter Eintrag dort wird dadurch nicht gelöscht. Beispiel: „Milch“ steht schon in Alexa → vorhandenen Eintrag zuordnen; „Milch“ fehlt dort wirklich → bewusst erneut anlegen; Alexa soll diesen Artikel nicht verwalten → nur lokal behalten. Bei bereits gelöschten Artikeln geht es stattdessen um einen möglicherweise übrig gebliebenen Eintrag in Alexa: gezielt zuordnen und löschen oder die Rückfrage ohne Änderung der verbundenen Liste abschließen. Abgeschlossene Rückfragen gelöschter Artikel werden nicht als vorhandene „nur lokale Artikel“ angezeigt. Offene Entscheidungen und bewusst nur lokal gespeicherte Artikel werden in der Statusanzeige getrennt von einem vollständigen Abgleich benannt. Wird ein Artikel nach Öffnen des Dialogs gelöscht, ist die alte Entscheidung ungültig und muss neu geprüft werden.
- Bestätigungen, Löschvermerke und Quellzuordnungen bleiben derzeit dauerhaft im HA-Store erhalten. Eine spätere Bereinigung benötigt ein gesondertes Verfahren für sehr lange offline gebliebene Geräte; sie erfolgt nicht stillschweigend nach einer Zeitspanne.

Die Frontend-Synchronisationsregressionen stehen unter `/tests/frontend/sync.html`: echte IndexedDB-Transaktionen mit simuliertem Server für verlorene Antworten, Wiederholungen, Metadaten, Löschungen und inaktive Listen. Beide Browser-Testseiten greifen nicht auf echte HA-Daten zu.

Die PWA speichert ein Home-Assistant-Refresh-Token lokal im Browserprofil, damit sie unabhängig von der HA-Companion-App synchronisieren kann. Die Anmeldung wird über den offiziellen Home-Assistant-Autorisierungsdialog erteilt. Beim Verbinden aus der HA-Seitenleiste öffnet die App ein eigenes Browserfenster bzw. einen neuen Tab und startet dort automatisch die Anmeldung. Bitte das Öffnen dieses Fensters erlauben und dort fortfahren. Danach öffnet sich die eigenständige App; die gewählte Liste bleibt im Rücksprung erhalten. Die ursprüngliche HA-Ansicht verbindet sich ebenfalls, sobald die Anmeldung im selben Browserprofil unter derselben Adresse gespeichert wurde. So kann HA die OAuth-Parameter korrekt auswerten, statt „Invalid redirect URI“ anzuzeigen. Bei blockierten Popups erscheint ein Hinweis auf den direkten App-Link unter **Installation**. Browserdaten nicht löschen, solange lokale Änderungen ausstehen; danach muss die App erneut verbunden werden. Der erste Offline-Sync verwendet stabile Aktions-IDs, damit ein nach Verbindungsabbruch wiederholter Artikel nicht doppelt angelegt wird. Bei gleichzeitigen Offline-Änderungen derselben Eigenschaft gilt die zuletzt synchronisierte Aktion; andere Eigenschaften desselben Eintrags bleiben davon unberührt.

### Mehrere Einkaufslisten

Die kleine Markenzeile bleibt **EINKAUFSZETTEL**; die große Überschrift zeigt den Namen der ausgewählten Liste. Direkt darunter lässt sich beispielsweise zwischen **Kaufland**, **Edeka** und **Baumarkt** wechseln.

- Neue Quelllisten weiterhin über Alexa anlegen und in HA bereitstellen. Die App erkennt externe HA-To-do-Listen automatisch unter **Setup → Listen verwalten**; eigene Einkaufszettel-Entitäten werden ausgeschlossen. Die Web-App legt keine Alexa- oder HA-Quelllisten an.
- Dort **In App anzeigen** über das Kontrollkästchen wählen, einen **App-Namen** vergeben und **Übernehmen** drücken. Der Alias wird zentral in HA gespeichert; Alexa- und HA-Quellnamen bleiben unverändert. Intern wird bei Bedarf automatisch ein quellgebundener Integrationseintrag mit eigenem Speicher angelegt; ein separater HA-Konfigurationsdurchlauf entfällt.
- Bestehende zusätzliche `todo`-Entitäten der Einkaufszettel-Integration werden beim Laden entfernt. Die externen Alexa-/HA-Quelllisten werden nicht entfernt oder umbenannt.
- Nach der Anmeldung werden alle geladenen Einkaufszettel-Listen angeboten und für den Offline-Zugriff zwischengespeichert. Bereits geladene Listen lassen sich auch ohne Netz wechseln.
- Artikel hinzufügen, abhaken und entfernen wie bisher; zum Bearbeiten des Namens den Artikelnamen antippen. Jede Liste hat ihre eigenen Artikel und ihre eigene Offline-Warteschlange.
- Beim Synchronisieren werden auch ausstehende Änderungen anderer verfügbarer Listen übertragen. Neue bzw. noch nicht zwischengespeicherte Listen benötigen zunächst eine Verbindung.
- **Quelllisten abgleichen** im Setup führt den automatischen Abgleich einschließlich der vorgemerkten App-Änderungen aus. Der bisherige HA-Kopierbutton und die alte Kopier-API bleiben für kompatible manuelle Übernahmen erhalten; auch sie bewahren Synchronisationsdaten und respektieren Löschvermerke.
- Ausgeblendete Listen verschwinden nach dem Online-Abgleich auch aus der Offline-Auswahl. Ihre internen Daten und ausstehenden Offline-Aktionen bleiben erhalten; ausstehende Aktionen werden nach erneutem Einblenden synchronisiert. Ohne Netz können Listen verwendet, aber keine gemeinsamen Einstellungen geändert werden.

## Daten und Grenzen

- Die Config Entry speichert Quell-Entity-ID und Listenname, keine Zugangsdaten.
- Die maßgebliche lokale Liste liegt dauerhaft im integrationsverwalteten HA-`Store` unter `.storage/einkaufszettel.<entry_id>`. Die PWA speichert den letzten Stand und ausstehende Aktionen zusätzlich gerätegebunden in IndexedDB.
- Die PWA greift über die authentifizierte WebSocket-API auf den integrationsverwalteten HA-Speicher zu. Eine zusätzliche `TodoListEntity` ist nicht erforderlich. Der Store enthält Artikel, Zusatzinformationen, Listenrevision, Aktionsbestätigungen, Löschvermerke und Quellabgleichsdaten zusammen in einem Snapshot. Bestehende Stores ohne Synchronisationsdaten werden beim ersten Schreibvorgang ergänzt; ungültige Synchronisationsdaten lösen einen ausdrücklichen Ladefehler statt eines Neuimports aus.
- Änderungen werden vor Anzeige dauerhaft gespeichert. Fehler werden nicht als Erfolg oder leere Liste verschleiert.
- Entfernen der Integration löscht weder den HA-Store noch Browserdaten automatisch. Backups verwenden und `.storage` nicht manuell bearbeiten.
- Der HA-WebSocket-Zugang und damit die erste Anmeldung sowie Synchronisation benötigen eine Verbindung zu Home Assistant. Bereits installierte App-Shell und zwischengespeicherte Liste sind offline verfügbar.

## Entwicklung und Tests

```text
python -m pip install -r requirements-dev.txt
python -m pytest tests/unit
ruff check .
ruff format --check .
```

Die HA-Integrationssuite ist für Linux/CI über [requirements-test-ha.txt](requirements-test-ha.txt) vorgesehen:

```text
python -m pip install -r requirements-test-ha.txt
python -m pytest
```

Die lokalen Modell-, Paket- und Lifecycle-Tests laufen unter Windows/Python 3.13. Die echte HA-Integrationssuite benötigt eine native Test-Abhängigkeit, die auf Windows Microsoft-C++-Build-Tools voraussetzt; daher wurde sie hier nicht ausgeführt. Die PWA muss außerdem auf den konkreten Android-/iOS-Geräten und mit dem Nabu-Casa-Zugang getestet werden.
